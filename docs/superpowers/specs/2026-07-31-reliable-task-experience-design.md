# 可靠任务体验设计

## 目标

在不新增 Redis、数据库或独立 worker 服务的前提下，为 PyGeoModel 提供可见的本地任务队列、预计等待时间、取消与失败恢复，并降低大三维资产和大结果图层对用户工作流的影响。

## 决策

- 使用应用内 `TaskScheduler`，默认同时执行一个任务，可由 `PYGEOMODEL_MAX_CONCURRENT_TASKS` 配置。
- 任务记录保留在现有 `data/tasks`；调度元数据单独持久化，不迁移现有任务 JSON 结构。
- 新建及重跑任务先入队，再由调度器调用既有 worker。服务启动时，排队任务重新入队；被中断的运行任务保留为可恢复失败任务。
- 取消排队任务立即生效。运行任务被标记为取消请求，worker 在进度回调检查点安全退出。
- 前端使用同一套退避轮询策略管理普通与多雷达任务。任务中心只展示服务返回的队列与预估信息。
- GLB 超过预算时先尝试降低可视化精度；仍无法满足时输出结构化警告，不让主计算结果因可选三维预览失败。
- GeoJSON 只在用户显隐或聚焦对应结果层时加载。

## 非目标

- 不实现多实例共享调度、跨主机取消或分布式队列。
- 不改变雷达及其他模型的科学计算口径。
- 不在本次修改中重构所有任务存储模块为数据库。

## 验收

1. 第二个任务在并发上限已满时显示排队位置和预计等待，前一个完成后自动启动。
2. 排队任务可立即取消；运行任务在下一个安全检查点结束并显示已取消。
3. 多雷达状态请求短暂失败后继续退避轮询并恢复。
4. 超预算 GLB 不会使任务整体失败，结果包含可读 warning。
5. 隐藏的结果图层不发起 GeoJSON 请求。
6. 后端测试不再产生 NumPy 2.5 的 shape 弃用警告。
