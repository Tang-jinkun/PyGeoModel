# 雷达 GLB 扫描扇面显隐设计

## 目标

为雷达覆盖结果 GLB 中随方位旋转的扫描扇面提供独立的显隐控制。关闭扫描扇面时，雷达实体、探测范围、探测底面、格网和其他 GLB 内容保持不变。

## 范围与约束

- 只控制当前 GLB 中语义明确的 `scan_slice` 节点。
- 不做历史 GLB 或缺少 `scan_slice` 语义节点的兼容处理。
- 不修改雷达计算公式、扫描动画数据和后端输出接口。
- 不重新下载、重新解析或重新生成 GLB；显隐在已加载的 Three.js 场景节点上完成。
- “显隐”不等于暂停动画：节点隐藏时动画时间继续推进，重新显示后呈现当前扫描相位。
- 雷达平台 GLB 的转台、天线和馈源旋转不受此开关影响。

## 方案

### 场景资源层

`prepareStaticScene` 在准备 GLB 时收集 `userData.kind === "scan_slice"` 的节点，并将这些节点记录到 `PreparedSceneGlb`。扫描节点为空时，场景资源不提供扫描控制能力。

`sceneGlbLayer` 在注册场景时接收初始扫描显隐状态，并提供按任务/资源切换扫描节点显隐的函数。切换只更新节点的 `visible` 属性并触发地图重绘，不改变场景注册、动画混合器或其他节点。

### 状态与交互层

`SceneGlbOverlayState` 增加扫描显隐状态，默认值为 `true`。用户在 GLB 图层行中通过独立的“扫描扇面”开关控制它；GLB 主开关仍然负责整个 GLB 的加载和移除。

当扫描开关先于 GLB 加载被操作时，状态先保存在任务资源状态中；GLB 加载完成后使用该状态初始化节点显隐。关闭 GLB 再重新打开时，保留扫描开关状态。

单雷达和多雷达都按资源分别控制：每个 `scene_glb` 资源有自己的扫描开关；`radar_platform_glb` 不显示该控制项。

## 数据流

```text
GLB scan_slice 节点
        ↓ parse / prepare
PreparedSceneGlb.scanNodes
        ↓ addSceneGlbLayer
场景层注册扫描节点
        ↓ 用户切换“扫描扇面”
setSceneGlbScanVisibility
        ↓
scanNodes[].visible = true / false
        ↓
地图重绘，动画继续沿用当前时间相位
```

## 错误处理

- 没有 `scan_slice` 节点的 GLB 不抛异常，也不显示扫描控制项。
- 目标场景资源尚未注册时，只更新状态，不调用渲染层。
- 目标资源已被移除时，切换操作返回失败并保持应用稳定。
- 现有 GLB 加载、颜色、格网、定位和资源清理流程保持不变。

## 测试验收

新增或调整测试覆盖：

1. GLB 准备阶段收集 `scan_slice` 节点。
2. 场景层可将全部扫描节点设置为隐藏或显示，且不影响其他节点。
3. 资源未加载时切换状态，随后加载使用保存的状态。
4. 关闭资源再重新打开后扫描状态保持。
5. 图层控制项仅对 `scene_glb` 显示，并正确发出扫描显隐事件。
6. 单雷达和多雷达资源分别控制，平台 GLB 不出现扫描控制项。
7. 现有前端测试、构建和 `git diff --check` 通过。
